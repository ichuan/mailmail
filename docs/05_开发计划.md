## P1：IMAP IDLE 后台推送

**目标**：收到新邮件时桌面通知，无需手动刷新。

**实现点**：
1. `imap.rs` 新增 `idle_watch(account, app_handle)`：独立 Tokio task，维持 IDLE 连接
2. 有新邮件时通过 `app_handle.emit("new_mail", account_id)` 推送前端
3. `App.tsx` 用 `listen("new_mail", ...)` 自动触发 `sync_folder`
4. 账号删除时需要取消对应 idle task（通过 `CancellationToken` 或 `oneshot` channel）

**测试**：单测较难（依赖真实服务器），以集成测试或手动验证为主

## P1：邮件本地缓存落地

**目标**：每次同步后将邮件写入 SQLite；启动时先从 DB 读取缓存，再在后台同步最新数据。

**现状**：`db.rs` 已有 `upsert_email`、`get_emails_by_folder`，但 `sync_folder` 命令还未调用它们；前端启动时直接从 IMAP 拉取，冷启动慢。

**实现点**：
1. `main.rs` / `sync_folder`：拿到 `Vec<Email>` 后逐条 `db.upsert_email()`
2. 新增 `get_cached_emails(account_id, folder)` 命令：从 DB 读取，供前端快速渲染
3. `App.tsx`：启动时先 `get_cached_emails`（即时显示），再异步 `sync_folder`（刷新最新）

**测试**：
- Rust：`sync_folder` 后查 `get_emails_by_folder` 条数正确
- 前端：mock invoke，验证先显示缓存再更新的加载流程

## P2：删除邮件

**目标**：用户点击垃圾桶图标，邮件从 IMAP 服务器删除，并从本地 DB 和 UI 移除。

**实现点**：
1. `imap.rs` 新增 `delete_email(account, folder, uid)`：
   - `STORE uid +FLAGS \Deleted`
   - `EXPUNGE`
2. `main.rs` 注册 `delete_email` 命令
3. `db.rs` `delete_email(account_id, folder, uid)` 已有，直接调用
4. `store.ts` 新增 `removeEmail(accountId, folder, uid)` action
5. `InboxView.tsx` 垃圾桶按钮调用 invoke → 更新 store

**测试**：
- Rust：`delete_email` 对 mock session 调用正确的 STORE/EXPUNGE
- 前端：mock invoke 成功后 store 中对应邮件消失

## P3：本地全文搜索

**目标**：在邮件列表顶部输入关键词，实时过滤发件人、主题、正文。

**实现点**：
1. `db.rs` 新增 `search_emails(query, account_id, folder)`：
   ```sql
   SELECT * FROM emails
   WHERE account_id = ? AND folder = ?
     AND (subject LIKE ? OR sender LIKE ? OR body_text LIKE ?)
   ORDER BY timestamp DESC LIMIT 50
   ```
2. `main.rs` 注册 `search_emails` 命令
3. `store.ts` 新增 `searchQuery` 状态和 `setSearchQuery` action
4. `InboxView.tsx` 顶部加搜索框，300ms debounce 后 invoke `search_emails`，结果覆盖显示列表（不改变 `emails` 主列表）

**测试**：
- Rust：插入3封邮件，搜索关键词只返回匹配项
- 前端：输入关键词后 invoke 被调用，列表正确过滤
