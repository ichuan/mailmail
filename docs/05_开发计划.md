## 已完成里程碑

### 核心功能（全部完成）

- 账号 CRUD（IMAP/SMTP 配置持久化）
- 多文件夹 IMAP 同步（inbox / sent / trash）
- 邮件本地缓存：SQLite `upsert_email` + 启动时先读缓存再后台刷新
- 删除邮件（服务器端 `STORE \Deleted + EXPUNGE`，DB + Store 同步，带确认对话框）
- SMTP 发件（含 Reply / Forward，RFC 引用格式）
- 本地全文搜索（SQLite LIKE，300ms debounce）
- 设置持久化（syncLimitDays、showImages）
- 附件支持（multipart 解析、`get_attachments` / `save_attachment` 命令、阅读面板下载 UI）
- IMAP IDLE 实时推送（Rust 后台 task，`mail:new` 事件推送前端）
- Windows Keychain（`keyring` v3 `windows-native`，密码不再明文存 SQLite）
- RFC 2047 头部解码（Q/B encoding，GBK/Big5/ISO 多字节字符集支持）

### Bug Fix Sprint（完成）

| Bug | 根因 | 修复 |
|-----|------|------|
| 链接点击劫持整个 WebView | `<a>` 在 `dangerouslySetInnerHTML` 内直接导航 | `tauri-plugin-shell` `open()` 在系统浏览器打开 |
| 时间戳只显示 `h:mm a` | 硬编码格式 | `smartFormatTime`：<1h→"32m"，<24h→"3h"，同年→"Mar 24"，更早→"2025/1/2" |
| "to me" 硬编码 | `To:` header 未解析 | 全管道修复：imap.rs → `recipient` 字段 → DB → Store → UI |
| HTML 邮件行间距过大 | `whitespace-pre-wrap` 应用于 HTML 容器 | 移除容器级样式，仅在纯文本分支应用 |
| HTML 邮件 CSS 被剥除 | `ammonia::clean()` 默认不保留 `style` | 改用 `Builder` 允许 `style` 属性 |
| 图片不显示 | ammonia 默认剥除 `<img>` | `Builder` 加白名单；JS 层按 `showImages` 开关剥除 |

### 稳定性加固 Sprint（完成）

| 项目 | 实现方式 |
|------|----------|
| IMAP IDLE 弱网恢复 | `idle_watcher` 指数退避（5s 到 300s）、失败计数、恢复后重置，并发出 `mail:connection-status` 状态事件 |
| SQLite 长运行并发 | 启用 WAL、`synchronous=NORMAL`、`busy_timeout=5000`、pool `max_connections=10` 与 `acquire_timeout=5s` |
| SMTP 发送稳定性 | `send_email` 20s timeout；transient 错误最多重试 2 次，退避 5s / 10s；永久错误直接返回 |
| 删除邮件防卡死 | `UID STORE` 与 `EXPUNGE` 初始化/stream 消费均增加 timeout |
| 大附件保护 | 单附件 10MB、单邮件总附件 50MB；超限附件跳过存储并记录日志 |
| HTML 邮件链接安全 | iframe 链接只允许 `http` / `https`，其他 scheme 阻断 |
| 前端事件清理 | iframe click listener 与 Tauri `listen('mail:new')` race 均补 cleanup |
| 前端内存边界 | Store 每 account+folder 保留最近 500 封，额外最多 100 封 starred，当前选中邮件例外保留 |
| Compose/Toast 清理 | draft/contact/undo timers 卸载清理；draft localStorage 写失败可降级；Toast 最多 5 条并清理 timer |
| 测试环境稳定化 | Vitest/jsdom 使用确定性的内存 `localStorage`，草稿持久化测试恢复稳定 |
| Hook 副作用收敛 | 启动同步、文件夹同步、附件加载 effect 依赖补齐或改用稳定 ref/store 读取 |
| 结构化错误切片 | 后端新增 `AppError`/错误码模型，`sync_folder` 已返回结构化错误 |
| 插件搜索下沉 | `emails.search()` 改为异步调用后端 `query_emails`，避免插件扫描内存邮件数组 |

## 已知问题

| 问题 | 影响 | 建议方向 |
|------|------|----------|
| 大附件邮件正文加载慢 | body 全量存 SQLite TEXT | 仅存 preview，正文按需 fetch |
| 附件仍由 `mailparse` 读入后再判定大小 | 超大单封邮件仍可能有解析内存峰值 | 后续改用 IMAP BODYSTRUCTURE/分段 fetch |
| release 日志含邮箱地址 | 诊断有价值，但隐私敏感 | 评估用 accountId/hash 替代 |
| 多数 IPC 仍返回字符串错误 | 前端只能靠文案分类，稳定性诊断不够精确 | 逐步迁移到 `AppError`，优先同步/发送/删除 |
